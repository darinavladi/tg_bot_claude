# План: Telegram-бот-планировщик

**Цель.** Бот, которому вы пишете событие с датой и временем («Встреча с Аней 15.10 в 18:30»), а он сохраняет его, показывает расписание и вовремя напоминает.

**Репозиторий:** https://github.com/darinavladi/tg_bot_claude (сейчас пустой, начинаем с нуля).

---

## 0. Выбранный стек (и альтернативы)

| Что | Выбор по умолчанию | Почему | Альтернатива |
|---|---|---|---|
| Язык | Python 3.12 | простой, много примеров для ботов | Node.js (grammY / Telegraf) |
| Библиотека бота | aiogram 3 | асинхронная, современная, есть FSM для диалогов | python-telegram-bot 21 |
| Хранение | SQLite (через SQLAlchemy 2 + aiosqlite) | один файл, без отдельного сервера | PostgreSQL, если пользователей станет много |
| Напоминания | APScheduler 3 с хранилищем задач в SQLite | задачи переживают перезапуск бота | свой цикл «раз в минуту проверять БД» |
| Разбор даты | dateparser (русский язык) + свой формат как запасной | понимает «завтра в 9», «15 октября 18:30» | только строгий формат `ДД.ММ.ГГГГ ЧЧ:ММ` |
| Хостинг | небольшой VPS (Hetzner, Timeweb, Selectel) + Docker | бот работает 24/7, полный контроль | Railway / Render / fly.io (проще, но бесплатные тарифы засыпают) |

## 1. Подготовка (день 1)

1. Создать бота у **@BotFather**: `/newbot`, получить **токен**. Токен никому не показывать и не коммитить.
2. Установить Python 3.12, Git, редактор (VS Code / PyCharm).
3. Склонировать репозиторий, создать виртуальное окружение:
   ```bash
   git clone https://github.com/darinavladi/tg_bot_claude.git
   cd tg_bot_claude
   python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
   pip install aiogram sqlalchemy aiosqlite apscheduler dateparser python-dotenv
   pip freeze > requirements.txt
   ```
4. Создать `.env` (с `BOT_TOKEN=...`, `TZ=Europe/Moscow`) и `.gitignore` (`.env`, `.venv/`, `*.db`, `__pycache__/`).

**Готово, когда:** окружение собрано, токен лежит в `.env`, `.env` не попадает в git.

## 3. Этап 1: «Эхо-бот» (MVP-скелет)

- `/start` отвечает приветствием, `/help` выводит список команд.
- Бот запускается в режиме long polling (`dp.start_polling(bot)`).

**Готово, когда:** бот отвечает в Telegram на `/start`. Первый коммит и пуш.

## 4. Этап 2: База данных

Таблицы:

- **users**: `id` (Telegram user id), `timezone` (например `Europe/Moscow`), `created_at`.
- **events**: `id`, `user_id`, `title`, `starts_at` (хранить в **UTC**), `remind_before_min` (по умолчанию 0 и/или 15/60), `status` (`active` / `done` / `cancelled`), `created_at`.

Правило: в БД всё в UTC, пользователю всегда показываем в его часовом поясе.

**Готово, когда:** таблицы создаются при старте, есть функции `add_event`, `list_events`, `get_event`, `delete_event`, `mark_done`.

## 5. Этап 3: Добавление событий

Два способа (делаем оба):

1. **Быстрый:** просто написать боту текст: `15.10 18:30 Встреча с Аней` или `завтра в 9 стоматолог`.
   - `parser.py` сначала пробует строгий формат `ДД.ММ[.ГГГГ] ЧЧ:ММ текст`, потом `dateparser` (`languages=['ru']`, `PREFER_DATES_FROM='future'`).
   - Бот отвечает подтверждением: «📅 Встреча с Аней — ср, 15 октября, 18:30. Сохранить?» с кнопками **✅ Сохранить / ✏️ Изменить / ❌ Отмена**.
2. **Пошаговый:** команда `/add` → бот спрашивает название → дату → время → когда напомнить (FSM aiogram).

Проверки: дата в прошлом → переспросить; дату не удалось разобрать → показать пример формата.

**Готово, когда:** оба способа сохраняют событие в БД, ошибки ввода обрабатываются понятными сообщениями.

## 6. Этап 4: Напоминания

- При сохранении события `scheduler.py` ставит задачу APScheduler `DateTrigger` на `starts_at − remind_before_min` (и, по желанию, второе напоминание в момент начала).
- `job_id = f"event:{id}:{offset}"`, чтобы можно было снять/перенести задачу.
- Хранилище задач APScheduler — `SQLAlchemyJobStore` на той же SQLite, чтобы напоминания не терялись при перезапуске. Дополнительно при старте бота: пройтись по активным будущим событиям и восстановить недостающие задачи; пропущенные (бот был выключен) — отправить с пометкой «пропущено».
- Сообщение-напоминание: «⏰ Через 15 минут: Встреча с Аней (18:30)» с кнопками **✅ Готово / 💤 Отложить на 10 мин / 💤 на 1 час**.

**Готово, когда:** напоминание приходит вовремя, в т.ч. после перезапуска бота; удаление события снимает напоминание.

## 7. Этап 5: Просмотр и управление расписанием

- `/today`: события на сегодня.
- `/week`: на 7 дней, сгруппировано по дням.
- `/list`: все будущие события (по 10 на страницу, кнопки ◀️ ▶️).
- У каждого события кнопки: **✏️ Изменить** (название / дата / время / напоминание), **🗑 Удалить**.
- Изменение даты/времени автоматически переставляет напоминание.

**Готово, когда:** любое событие можно найти, изменить и удалить через кнопки.

## 8. Этап 6: Удобства (после MVP)

По приоритету:

1. **Часовой пояс:** выбор при `/start` (кнопки с популярными поясами или отправка геопозиции).
2. **Утренняя сводка:** каждый день в 08:00 по поясу пользователя список дел на сегодня (`/settings` вкл/выкл и время).
3. **Повторяющиеся события:** ежедневно / еженедельно / ежемесячно (поле `repeat_rule`, после срабатывания создаётся следующее).
4. **Настройка напоминаний по умолчанию** в `/settings` (за 10 мин / 1 ч / 1 день).
5. **Категории / теги** и цвета-эмодзи.
6. **Голосовые сообщения** → текст (Whisper) → событие. По желанию.
7. **Разбор свободного текста через LLM** для сложных фраз («в следующую пятницу после работы»). По желанию.
8. **Экспорт в .ics** / синхронизация с Google Calendar. По желанию.

## 9. Этап 7: Тесты и качество

- `pytest` + `pytest-asyncio`.
- Обязательно покрыть тестами: `parser.py` (много вариантов фраз, граница года, «завтра» около полуночи), перевод часовых поясов, CRUD в `repo.py` (на временной БД).
- Линтер/форматтер: `ruff` (`ruff check`, `ruff format`).
- GitHub Actions: на каждый пуш запускать ruff + pytest.

**Готово, когда:** CI зелёный, ключевая логика покрыта тестами.

## 10. Этап 8: Деплой

1. `Dockerfile` (python:3.12-slim, `pip install -r requirements.txt`, `CMD ["python", "-m", "bot"]`) и `docker-compose.yml` с томом для файла БД и `restart: unless-stopped`.
2. Арендовать VPS (1 vCPU / 1 ГБ хватит), поставить Docker.
3. Скопировать `.env` на сервер вручную (не через git), `docker compose up -d`.
4. Логи: `logging` в stdout, смотреть `docker compose logs -f`.
5. Бэкап: раз в сутки копировать файл `*.db` (cron).
6. Обновление: `git pull && docker compose up -d --build` (позже можно автоматизировать через GitHub Actions).

**Готово, когда:** бот работает 24/7 на сервере и переживает перезагрузку сервера.
